# Website-only image imports
Continues commit 81b83dc. Photography is never committed to GitHub. Canonical website copies use a private Blob store under images/rent/ and are served through a manifest-restricted website image route. Drive originals remain unchanged.
Website-use and download/store permission confirmed through partner on 9 November 2026 (internal reference PE-WEB-20261109-TER). Permission evidence and source/customer metadata remain private. This does not authorize Public GitHub photography or social posts.
scripts/import-private.mjs consumes a privately prepared inventory containing current available rows, exact folder IDs, photo file IDs enumerated by the authorized Drive connection, websitePermission:true, publicRepositoryPermission:false, and evidence reference. Set BLOB_READ_WRITE_TOKEN server-side, never in Git. Run a two-listing sample with PE_IMPORT_LIMIT=2 before bulk. The local dependency versions match package.json. Every imported copy is decoded, resized and stripped of metadata, uploaded privately and byte-compared with a private readback. Source hashes identify duplicates; cross-listing matches are flagged for review because facilities may be shared. Full SHA-256 paths avoid collisions. Existing originals and production assets are untouched.
The private manifest is manifests/listing-images-v2.json; it contains source mappings and is never placed in a public repository. Only listing facts and same-origin website image paths reach the browser. The image handler serves only approved manifest entries and never returns storage credentials, source URLs or the evidence screenshot.
Current import is an operator-triggered snapshot. Recheck live Sheet availability before a rerun; do not claim unattended sync. Visual property identity requires source confirmation where a photo has no independently identifiable unit label.
